# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Grav 2 plugin (Grav 2.2.18+, **Admin2** + **API** plugin, PHP 8.1+) that replaces the page content editor with a TipTap/ProseMirror visual editor while keeping **Markdown as the saved format**. Raw HTML, Twig and shortcode blocks (including nested shortcodes) must round-trip byte-for-byte. Independent of the commercial Editor Pro — never copy code from it. Since v2.0 the classic Admin (Grav 1.7, `onAdmin*` events, Twig assets, admin tasks) is **not** supported: Admin2 is a SvelteKit SPA that never runs those hooks.

## Commands

```sh
npm install
npm test                                   # node --test tests/*.test.mjs (jsdom, no browser)
node --test --test-name-pattern="tables" tests/markdown.test.mjs   # single test by name
npm run build                              # esbuild → dist/visual-editor/ + .zip + SHA256SUMS, and refreshes admin-next/fields/visual-editor.js
php tests/php/run.php                      # PHP tests (no PHPUnit: Grav stubs in tests/php/stubs.php); also run by npm test
for f in visual-editor.php classes/*.php; do php -l "$f"; done   # syntax check
```

There is no linter. Real Admin2 behaviour can only be verified on a running Grav 2 site. Reference sources of Admin2 (`grav-admin-next`, `grav-plugin-admin2`), the API plugin and shortcode-core can be cloned into `.research/` (gitignored) to check contracts.

### Environment and known issues (as of 2026-11-09)

- `node_modules/` was originally installed on Windows. On Linux, esbuild needs its platform binary: `npm install --no-save @esbuild/linux-x64@<esbuild version>` (both binaries can coexist).
- Tests assign `navigator` (and other jsdom globals) with `Object.defineProperty` because Node 21+ defines a getter-only global.
- The build starts with `rm -rf dist`. `CHANGELOG.md` uses Grav's GPM format; `THIRD-PARTY-NOTICES.md` is generated by the build (in `dist/` and at the root) from esbuild's metafile: every bundled package with its license, grouped by identical text; a bundled package without a license text fails the build. TipTap's npm packages ship none, so `licenses/tiptap-LICENSE.md` (from their repository) is used for `@tiptap/*`.
- List items use `FlexibleListItem` (`content: 'block+'`) instead of TipTap's `paragraph block*`, otherwise ProseMirror hoists a leading blockquote/block out of the list on load. Continuation lines are indented to the marker width (2 for `- `, 3 for `1. `, 4 for `10. `).
- `protectBlocks` also protects fences opened on a list item line (`- ```js`, `1. ~~~`): the marker stays outside the placeholder and the stored source is dedented to the item content column. Any line-based detection added there must consider this list prefix.
- Saving keeps the page's conventions: `detectMarkdownStyle()` reads bullets, ordered delimiter, `_`/`__`, `***`, setext headings, two-space hard breaks, autolinks and table outer pipes at load, and `documentToMarkdown(doc, style)` writes them back (defaults = the historic output). Lists carry a `tight` attribute (from marked's HTML) so tight nested lists stay tight. `escapeMarkdown` leaves `*`/`_` bare where they cannot delimit emphasis. Still normalized: HTML entities (decoded) and malformed inline code.
- Never register a Twig path or load a file the build does not ship: a missing directory makes Twig throw and takes the whole site down (front end included).

## Architecture

### JS (`src/`, bundled as one ES module)

- `src/markdown.js` — pure string/ProseMirror helpers, unit-tested directly. **Load path**: `protectBlocks()` replaces fenced code, HTML/Twig blocks (lines starting with a tag, `{{`, `{%`, `{#` up to a blank line) and shortcode blocks (`extractShortcode` matches nested open/close tags) with `<ve-protected data-kind data-source>` placeholders before Markdown parsing; `protectInline()` does the same for inline HTML/Twig/shortcodes. Placeholder sources are entity-encoded (`encodeSource`) so marked and the inline pass cannot split them. **Save path**: `nodeToMarkdown` / `inlineNodeToMarkdown` serialize the ProseMirror doc to Markdown by hand.
- `src/extensions.js` — TipTap schema: `ProtectedBlock` (atom node holding `source` + `kind`; host hooks `preview`/`editSource`/`notify` passed via `config.hooks`), `InlineRaw`, alert blockquotes, extra inline marks, `FlexibleListItem`, aligned table cells, `ImageWithSource` (keeps the Markdown path in `src`, displays `resolveMedia(...)`), and the block drag handle: one element beside the document (a plugin `view`, not a decoration — a decoration is rebuilt on selection changes and vanished when pressed) that selects the cursor's top-level block and sets `view.dragging`; ProseMirror's drop handler does the move. `markdownToHtml()` = `protectBlocks` → `markdownTables` → `marked` → `githubAlerts` → `addMediaAttributes`. `sanitizePreview()` strips active content from server preview HTML.
- `src/editor.js` — host-agnostic `VisualEditor(host, { markdown, config, services, onChange })`: lifecycle, toolbar, visual/source modes, sync. Feature areas live in `src/editor/` and are mixed into the prototype (`Object.assign(VisualEditor.prototype, …)`, same public methods): `blocks.js` (alignment, colored blocks, alerts, protected blocks), `tables.js`, `images.js` (media, upload, drag/paste, image bar), `dialog.js` (generic dialogs), `ui.js` (icons, labels, toolbar defaults, messages, `element()`). It reports only real user edits through `onChange` (never on mount or mode switch, so the page is not marked dirty), `setMarkdown()` ignores its own last output, `insertMarkdown()` inserts at the cursor. `services` = optional async `listMedia`, `upload`, `pickSiteMedia`, `preview`.
- `src/admin2-field.js` — the Admin2 custom field (`customElements.define(window.__GRAV_FIELD_TAG)`, i.e. `grav-visual-editor--visual-editor`). Contract from Admin2's `CustomFieldWrapper.svelte`: Admin2 sets `field` then `value` before connecting, listens for a `change` CustomEvent dispatched **on the element** with the Markdown in `detail`, and echoes every value back through the `value` setter. Services map to Admin2 globals: `__GRAV_PAGE_MEDIA`, `__GRAV_UPLOAD_PAGE_MEDIA`, `__GRAV_MEDIA_PICKER`, and API calls use `__GRAV_API_SERVER_URL` + `__GRAV_API_PREFIX` with the `X-API-Token` header. Admin2 treats every `change` from a custom field as a commit (undo entry + auto-save), so edits are batched: one `change` after `VisualEditorField.changeDelay` (400 ms) without typing, flushed immediately on focusout, Ctrl/Cmd+S (window capture listener, before Admin2's), `grav:editor:save` and disconnect — never dispatch `change` per keystroke. Tests set `changeDelay = 0` to get synchronous changes. It also handles Admin2's `grav:editor:insert-content` window event and follows `html.dark`. `assets/css/alerts.css` + `assets/css/editor.css` are inlined into the bundle (`__VE_CSS__` define) and injected as a `<style>` — Admin2 loads no stylesheet for the field, so every editor style must be in one of those two files.

**References, footnotes, inline images.** Link reference definitions (`[label]: url`) and footnote definitions (`[^id]: …`) are protected blocks; `resolveReferences()` turns usages into `<a data-ve-ref data-ve-ref-form>` so the `ReferenceLink` mark (which also adds the `title` TipTap's Link lacks) writes the same form back via `linkMarkdown()`. Footnote references `[^id]` are inline atoms. Images sharing a paragraph with text become `inlineImage` nodes (`data-ve-inline`); standalone images stay block `image` nodes. `inlineChildren()` writes one link around a run of nodes sharing a link mark. `protectInline()` skips inline code spans.

**Shortcode-backed blocks** (all editable containers parsed in `protectBlocks` before the generic shortcode protection, each tag alone on its line): colored blocks `[div class="ve-block" style="…"]` (optional `background-image` gradient: `colorBlockTag(color, open, gradient)` / `gradientFromOpen()`; directions in `gradientDirections`, shared with the page-background preview and mirrored by PHP `GRADIENT_DIRECTIONS`), alignment `[center]`/`[right]`/`[left]`/`[justify]` (shortcode-core's AlignShortcode), and per-table look `[div class="ve-table-plain|normal"]` around one table (`tableStyle` node, content `table`). They are wrapped at the document/container level only (`wrapBlocks`), never inside a list or quote, because shortcode-core only treats a tag as a block when it starts the line. The front-end CSS for plain tables (site option `plain_tables` and per-table class) is injected by `addTableStyles()` in PHP.

**Collaborative editing** (Admin2 + Sync plugin). Admin2 sets `yFragment`/`yAwareness`/`yUser` on the field before connecting; `src/collab.js` seeds an empty fragment from the page Markdown, starts from `initProseMirrorDoc()` (y-prosemirror) and adds `ySyncPlugin`/`yCursorPlugin`/`yUndoPlugin`; TipTap's history is disabled (`history: false`) and undo/redo use the shared history. The fragment is the source of truth: the `value` setter is ignored while collaborating, `replaceContent()` replaces explicitly. **Yjs must be one instance**: the build resolves `yjs` and `y-protocols/awareness` to relay modules (plugin in `build.mjs`) bound to Admin2's `window.__GRAV_YJS__` only when collaboration starts — never bundle Yjs, never touch Yjs at module load. `tests/bundle-collab.test.mjs` and `tests/bundle.test.mjs` check the built module with and without Admin2's Yjs (run after `npm run build`).

**Interface language.** `src/i18n.js` `t(english, params)` translates through `src/i18n/<locale>.js` (English strings are the keys; missing → English); the locale is Admin2's `window.__GRAV_I18N.locale` (else `<html lang>`), read when an editor is created. `dialog()`, `button()` and `notify()` translate their texts themselves; other UI strings call `t()`. `tests/i18n.test.mjs` fails when a UI string has no French entry or a translation loses a `{placeholder}` — add new strings to `src/i18n/fr.js`.

A Markdown round-trip change usually touches both directions: parse/protect in `markdown.js` + schema in `extensions.js` + serializer in `markdown.js`. Add a round-trip test (`roundTrip()` in `tests/markdown.test.mjs`). Field/host behaviour is tested in `tests/admin2-field.test.mjs`, which mimics Admin2's mounting.

### PHP

- `visual-editor.php` registers an autoloader for `classes/` (no vendor/) and subscribes to: `onAdminListContentEditors` (adds `visual-editor` to the profile's *Content editor* list — Admin2 fires this event), `onApiBlueprintResolved` (context `page`: finds the field named `content` at any depth, attaches the client config as `visual_editor`, and rewrites its type to `visual-editor` when `site_default` is on and the user's `content_editor` is empty/`default`/`visual-editor`), `onApiRegisterRoutes` (`POST /visual-editor/preview`), `onPageContentRaw` (optional front-end alert CSS), and `onTwigSiteVariables` (front end: paints the page with its `background_color` frontmatter by overriding Quark 2's `--q2-bg`/`--pico-background-color` and text variables on `html:root[data-theme]`, colors validated by `safeColor()`). The blueprint hook also inserts, right after the content field (`pageFields()`), `header.background_color`, `header.background_color_2` (gradient) and `header.background_direction` (`GRADIENT_DIRECTIONS`, mirrored in `src/admin2-field.js`); the field component watches them (`watch` + `formChanged()`) to tint the editing surface. With a gradient, the text color is picked on `mixColors()` (PHP and JS, parity-tested) and theme surfaces become transparent. `header.page_effect` (option `page_effects`, values = `PAGE_EFFECTS` keys) is appended after them; `addPageEffect()` (also `onTwigSiteVariables`) writes CSS only: `body::before`/`body::after` fixed, `pointer-events:none`, tiled `radial-gradient` dots moved by `transform`, a `prefers-reduced-motion` rule stopping animations, particle colors picked from the page background's contrast. Labels of added fields go through `label()` in the user's Admin2 language (`adminLanguage()` via the API's `PreferencesResolver`), because they are added after the API's own label translation. Field lists are rebuilt by appending — never reuse numeric keys when inserting.
- `classes/PreviewController.php` extends the API plugin's `AbstractApiController`: with the page `route` the editor sends, it calls `authorizePageAction(…, 'update', 'api.pages.write')` (page-level rules) when the API has it, else requires `api.pages.write`; `classes/ShortcodePreview.php` calls shortcode-core's `processShortcodes()`, firing `onShortcodeHandlers` if no handler is registered yet for the API request, and falls back to escaped source.

### Config surface

Adding an option means updating `visual-editor.yaml` (defaults), `blueprints.yaml` (plugin form) and `clientConfig()` in `visual-editor.php`, plus `defaultConfig` in `src/editor.js` if the JS needs a default. The default toolbar list is duplicated in the YAML, the blueprint (default + description) and `defaults` in `src/editor.js`, and the contrast rule exists in PHP and JS: `tests/config.test.mjs` (and the shared `tests/fixtures/contrast.json`, also read by the PHP tests) fail when these copies drift. The version is in `package.json` (+ lockfile) and `blueprints.yaml`.
