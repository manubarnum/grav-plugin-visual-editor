# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Grav CMS plugin (Grav 1.7+, Admin 1.10+, PHP >= 7.3) that replaces the Admin page-content textarea with a TipTap/ProseMirror visual editor while keeping **Markdown as the saved format**. Raw HTML, Twig and shortcode blocks (including nested shortcodes) must round-trip byte-for-byte. Independent of the commercial Editor Pro — never copy code from it. README.md has the user-facing feature list, the JS extension API and the security model.

## Commands

```sh
npm install
npm test                                   # node --test tests/*.test.mjs (jsdom, no browser)
node --test --test-name-pattern="tables" tests/markdown.test.mjs   # single test by name
npm run build                              # esbuild → dist/visual-editor/ + dist/visual-editor.zip + SHA256SUMS
for f in visual-editor.php classes/*.php; do php -l "$f"; done   # only PHP check; no PHP tests exist
```

There is no linter. Browser/Admin behaviour can only be verified on a running Grav site.

### Environment and known issues (as of 2026-11-09)

- `node_modules/` was originally installed on Windows. On Linux, esbuild needs its platform binary: `npm install --no-save @esbuild/linux-x64@<esbuild version>` (both binaries can coexist).
- The test file assigns `navigator` with `Object.defineProperty` because Node 21+ defines a getter-only global; keep that pattern for other jsdom globals that Node may add.
- The build starts with `rm -rf dist`. `CHANGELOG.md` uses Grav's GPM format; `THIRD-PARTY-NOTICES.md` is generated by the build, not copied.
- List items use `FlexibleListItem` (`content: 'block+'`) instead of TipTap's `paragraph block*`, otherwise ProseMirror hoists a leading blockquote/block out of the list on load. Continuation lines are indented to the marker width (2 for `- `, 3 for `1. `, 4 for `10. `).
- `protectBlocks` also protects fences opened on a list item line (`- ```js`, `1. ~~~`): the marker stays outside the placeholder and the stored source is dedented to the item content column. Any line-based detection added there must consider this list prefix, or the indented closing fence is misread as an opening one.
- Not handled yet: tight nested lists (`- A\n  - B`) are re-serialized as loose (blank line between blocks).
- The build copies only `classes/` and `assets/css/`: `assets/js/config.js` and `templates/` (empty, but registered as a Twig path) are not shipped. `config.js` is not referenced by any PHP file.
- `assets/js/editor.js` at the root is a committed copy of the bundle so the repo works as an installed plugin, but the build never writes it. After changing `src/`, run `npm run build` and `cp dist/visual-editor/assets/js/editor.js assets/js/editor.js` before committing.

## Architecture

### JS (`src/`, bundled as one IIFE)

- `src/markdown.js` — pure, DOM-free string/ProseMirror helpers, unit-tested directly. **Load path**: `protectBlocks()` replaces fenced code, HTML/Twig blocks (lines starting with `<`, `{{`, `{%`, `{#` up to a blank line) and shortcode blocks (`extractShortcode` matches nested open/close tags) with `<ve-protected data-kind data-source>` placeholders before Markdown parsing; `protectInline()` does the same for inline HTML. **Save path**: `nodeToMarkdown` / `inlineNodeToMarkdown` serialize the ProseMirror doc to Markdown by hand (tables via `tableCellToMarkdown`, pipes escaped).
- `src/extensions.js` — TipTap schema: `ProtectedBlock` (atom node holding `source` + `kind`, rendered by a node view with the optional server preview), `InlineRaw`, alert blockquotes (`BlockquoteWithAlert` + `AlertTitle`), extra inline marks, the drag handle plugin. `markdownToHtml()` = `protectBlocks` → `markdownTables` → `marked` → `githubAlerts` → `addMediaAttributes` (resolves page-relative image paths against `pageMediaUrl`). Turndown is only a fallback for unrecognized inline HTML, **not** the main serializer.
- `src/editor.js` — the `VisualEditor` UI (toolbar, dialogs, visual/source modes, media picker, uploads). `initialize()` enhances every `textarea[data-grav-editor]`, merges `window.GravVisualEditorConfig` over built-in defaults, and on any exception restores the original textarea. It syncs Markdown back into the textarea on change and on form submit (capture phase), so saving goes through Grav's normal page form. It emits `visual-editor:before-init|ready|change|save` on the textarea. `request(urlName, fields, file)` POSTs `FormData` (with `admin-nonce` and `page_route`) to the config URL named `uploadUrl` / `previewUrl` / `mediaUrl`.

A Markdown round-trip change usually touches both directions: parse/protect in `markdown.js` + schema in `extensions.js` + serializer in `markdown.js`. Add a round-trip test (`roundTrip()` helper in the test file) for it.

### PHP

- `visual-editor.php` (`VisualEditorPlugin`): admin-only features are gated on `enabled` + `isAdmin()`; asset injection additionally on `isPageEditor()` (URI under `<admin.route>/pages`). `onTwigSiteVariables` builds the client config (task URLs, page route/media URL, `admin-form` nonce, toolbar, upload limit = min(10 MB, PHP ini limits)); `onAssetsInitialized` (priority -1000) prints it as `window.GravVisualEditorConfig` and loads the CSS + deferred bundle, so it relies on the Twig var already being set. On the front end, `addAlertStyles` prepends a `<link data-visual-editor-alerts>` to raw page content.
- Endpoints are Admin **tasks**, not routes: `/<admin>/task:visualEditorUpload|Preview|Media`. `onAdminTaskExecute` intercepts `taskVisualEditor*`, stops propagation and calls `classes/AdminBridge::handleTask()`, which checks `admin.pages`, POST, the `admin-form` nonce and the page route, then answers JSON via `respond()` (which exits). Uploads: raster images (validated with `getimagesize`) and SVG, normalized names, random suffix on collision.
- `classes/ShortcodePreviewExtension.php` renders previews through `shortcode-core` when installed, otherwise returns escaped source. Twig/HTML are never executed for previews.

### Config surface

Adding an option means updating `visual-editor.yaml` (defaults), `blueprints.yaml` (Admin form) and the array in `onTwigSiteVariables`, plus the JS defaults in `initialize()` if needed. Existing gaps: `shortcode_previews` and `shortcodes` are read in PHP but have no blueprint field, and `shortcode_previews` has no YAML default. The default toolbar list is duplicated in the YAML, the blueprint (default + description) and `defaults` in `src/editor.js`. Version `1.0.0` is hard-coded in `package.json`, `blueprints.yaml` and the PHP config.
